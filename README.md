## frp 为什么非得有一台公网 IP 的机器

frp 是一套反向代理应用，支持 TCP、UDP、HTTP、HTTPS，作用是把没有公网 IP 的内网服务暴露到公网。它的结构固定为两端：有公网 IP 的云服务器上跑 frps（服务端），内网机器上跑 frpc（客户端）。frpc 主动向 frps 发起连接，外部访问云服务器的某个端口，请求就被转发到内网的真实服务上。

分工决定了买机器的思路。frps 只做中转，不跑业务逻辑，压力来自带宽和连接数，跟 CPU 核心数关系不大。所以你要买的是一台入口稳定、带宽够、防火墙能自己控制的机器，而不是一台高配机器。家里 NAS、公司内网开发机、树莓派这类没有公网 IP 的设备，靠它就能从外面访问。

## 在雨云上把 frps 和 frpc 配起来

先说最容易踩的坑：网上大量 frp 教程还停留在 `frps.ini` / `frpc.ini` 的年代，段落头写 `[common]`、字段写 `bind_port`、`local_ip`、`remote_port`。新版 frp 已经改成 toml 格式，字段名变成驼峰写法，照着旧教程抄会直接启动失败或配置不生效。下面给的是 toml 写法，以官方当前版本为准。

**服务端（雨云的机器上）**，新建 `frps.toml`：

toml
bindPort = 7000
auth.token = "换成一串足够长的随机字符"


`bindPort` 是 frpc 连过来的端口，`auth.token` 是两端共享的密钥。token 不要用生日、域名、`123456` 这类，它等同于你这台中转机的门钥匙。

启动：

bash
./frps -c frps.toml


正式用建议把 frps 交给 systemd 托管：写一个 unit 文件，`ExecStart` 指向 `frps -c` 加配置文件的绝对路径，设 `Restart=always`，然后 `systemctl enable --now` 起来。这样机器重启、进程崩了都会自动拉起，不用每次 SSH 上去手动敲。

**客户端（内网机器上）**，新建 `frpc.toml`。假设要把内网机器的 80 端口暴露到云服务器的 8080：

toml
serverAddr = "雨云服务器的公网IP"
serverPort = 7000
auth.token = "和服务端一模一样的那串字符"

[[proxies]]
name = "web"
type = "tcp"
localIP = "127.0.0.1"
localPort = 80
remotePort = 8080


启动：

bash
./frpc -c frpc.toml


两端程序从 frp 官方发布页下载，选对应操作系统和架构的包。0.68.0 起客户端界面改动很大，可以直接在图形界面里创建代理，不一定要手改配置文件；但服务端那一段 toml 还是得自己写。

### 端口放通这一步别省

云服务器要放通两类端口，缺一个都连不通：

- `bindPort`（示例 7000），给 frpc 连进来用；
- `remotePort`（示例 8080），给你从外部访问用。

端口没放通是内网穿透连不通最常见的原因。雨云的控制台有安全组/防火墙设置，两个端口都要加进去，协议选对（TCP 转发就放 TCP）。

## 连不通的时候按这个顺序查

先按 token、端口、连接状态三步走，不要一上来就重装：

1. **token 是否完全一致**。两端字符串必须逐字相同，前后多了空格、引号用了中文全角，都会连不上。
2. **端口是否放通**。`bindPort` 和 `remotePort` 两个都要在防火墙里开。只开了其中一个，表现是能连上但打不开，或者干脆连不上。
3. **frpc 有没有连上 frps**。看 frpc 的日志，成功时会出现 `start proxy success` 这类提示，服务端日志里能看到客户端登录信息和 `new proxy ... success`。

已经连上了但访问不到服务，查两件事：`remotePort` 是否真的放通了；内网服务是否确实跑在 `localPort` 上。本地 `curl 127.0.0.1:80` 通不通，先在内网机器上验一遍。

三条判据全过，链路才算打通：frps 正常运行且日志无报错；frpc 日志显示成功连上 frps；外部用“云服务器 IP:remotePort”能访问到内网服务的真实内容。

## 跑 frp 会不会被云厂商盯上

frp 常年出现在安全团队的内网穿透工具清单里，和 ngrok、ew、socat、iox、EarthWorm 这些并列，属于被重点监控的一类。公开的攻防研究里，可被检测的特征包括：进程名里带 frp；运行时有 `127.0.0.1:22` 这类本地监听和连接；未编译版本能通过 md5 指纹匹配；流量侧可以对登录包里的字段做规则命中，登录包会带 `version`、`hostname`、`os`、`arch`、`user`、`privilege_key`、`run_id`、`metas` 这些信息。

这些结论来自针对特定旧版本的研究，作者自己也说明方法“可能随时失效”，它说明的是穿透流量确实会被安全产品识别，不等于某一家服务商的具体策略。雨云没有公开的 frp 专项说明，我不能替它承诺什么。想确认，最快的办法是开工单问客服。

真正能降低风险的是配置本身：

- token 用足够复杂的随机串，别让人蹭你的中转；
- 只暴露确实需要的服务和端口，转发表里别留测试用的条目；
- 暴露出去的管理类页面（面板、数据库管理、路由后台）叠加一层访问鉴权，别裸奔；
- 只用来访问你自有的、合法合规的内网服务。

还有一条值得提前想清楚：国内节点如果要绑域名对外提供 Web 服务，备案是绕不开的流程，具体怎么走问客服比看文章靠谱。至于网上流传的“国内云厂商协议禁止内网穿透”，那是论坛里的个人转述，没有厂商公告原文，有人表示用了几年没事，也有人称收到过通知。下单前自己确认一遍条款，比事后扯皮省事。

## Docker 部署和第三方汉化镜像

不想在机器上装二进制，可以用 Docker 跑客户端：

bash
docker run --name frpc \
   --restart always \
   -e TZ=Asia/Shanghai \
   -v ./frpc.toml:/opt/frpc.toml \
   -d fatedier/frpc:v0.61.2 -c /opt/frpc.toml


镜像 tag 换成你实际用的版本，上面的 `v0.61.2` 只是示例，别照抄。

官方原版没有中文界面，有第三方作者做了汉化和对应镜像（`firfe/frps`、`firfe/frpc`，国内可从华为云镜像仓库拉），当前制作版本标注为 0.71.0。两点提醒：这是第三方作品，不是官方发布，出问题找原作者；镜像仓库里**没有 `latest` 标签**，必须写具体版本号，写 `latest` 会直接拉取失败。非 Docker 部署也想用汉化界面，可以下作者提供的静态资源，在配置文件的 `[webServer]` 段加 `assetsDir` 指向实际目录。

## 下单前确认这几件事

- **计费周期和续费价**：月付、季付、年付的折扣不一样，首期优惠和续费价也不是一个数，购买页会把周期写清楚，续费前再看一眼。
- **流量与带宽**：标“不限流量”的看带宽上限，标流量的看每月给多少 GB。frp 转发消耗不大，但如果你要转的是视频、下载这类，流量会跑得比想象快。
- **地域与备案**：国内节点延迟低，做站要走备案；香港、美国节点免备案，代价是国内访问延迟和线路波动。
- **能不能跑 frp**：条款和客服是唯一可靠来源。

最后给个选择规则。只做一两个 TCP 转发、自己用，国内 KVM 入门档就够，多花的钱换不来体验提升；要跑 Web 站、挂多个端口、或者几个人共用，看中配那一档的上行带宽和流量，那才是瓶颈所在；入口容易被扫、怕被打，再考虑高防机型。买之前先想清楚要暴露几个服务，比对着参数表纠结核心数有用得多。
